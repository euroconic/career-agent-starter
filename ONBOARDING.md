# Онбординг нового пользователя

Цель: настроить отдельный карьерный проект по ответам пользователя и его материалам. Не переносить сведения из примеров, других папок или памяти о другом человеке.

## Вариант 1: разговор с агентом

Если профиль уже существует, прочитай его и предложи продолжить с незаполненного шага. Не запускай настройку поверх файлов и не меняй подтверждённые факты без запроса.

Задавай вопросы небольшими группами, используя уже полученные ответы:

1. Как обращаться к пользователю? Какие роли и уровень он рассматривает? На каком языке обсуждать поиск и писать материалы?
2. Какие локации и формат работы подходят? Какие ограничения действительно важны? Зарплатные ожидания необязательны; если они указаны, уточни валюту, период и gross/net.
3. Есть ли исходное CV? Попроси указать его файл или предоставить текст. Если CV нет, начни с компаний, реальных должностей, дат и основных задач. Не считай целевую должность прошлым опытом.
4. Какие достижения пользователь может подтвердить? Для цифр уточни единицу, период и личный вклад. Если цифр нет, сохраняй конкретные качественные результаты.
5. Какой стиль и длина материалов ему подходят? Можно попросить короткий образец собственного текста, но не требовать его для начала.

После ответов создай частные файлы по шаблонам из `templates/`. При наличии Python можно использовать `tools/onboard.py --answers <private-json> --cv <source.md>`, затем удалить временную анкету только по правилам среды. Не сохраняй анкету вне `config/`. Скрипт принимает поля `name`, `target`, `language`, `location`, `constraints`, `style`; обязательны первые два. Пример с пустыми значениями: `templates/answers.example.json`.

Не называй импорт подтверждением фактов. Сохрани исходник отдельно, покажи пользователю извлечённые должности, даты и достижения, а спорные места обозначь как нерешённые. Подтверждение пользователем конкретных фактов запиши в `inputs/achievements.md` с источником. PDF/DOCX обрабатывай доступным документным инструментом; если его нет, попроси текст и не придумывай содержание.

При ручной настройке используй `templates/about.md` для `about.md`, `templates/profile.json` для `config/profile.json`, остальные одноимённые Markdown-шаблоны для путей из `.context/layout.md`. Создай `applications/index.json` с содержимым `{"applications": []}`. Не копируй `templates/application-record.md` в трекер до появления настоящей вакансии. После импорта укажи относительный путь исходника в `source_cv` и статус `source_cv_review: "unverified"`.

`inputs/master_cv.md` после импорта становится защищённым источником. Его дополнение требует явного запроса пользователя. До этого можно вести уточнения в `inputs/achievements.md` и контексте приложения.

## Вариант 2: локальная анкета

Из корня новой копии запусти:

```sh
python3 tools/onboard.py
```

Скрипт создаёт профиль, предпочтения по стилю, пустой трекер и места для источников. Можно указать текстовое CV через `--cv path/to/cv.md`; поддерживаются только `.md` и `.txt`. Файл копируется, оригинал не меняется. Если CV пока нет, это явно отмечается. Скрипт откажется перезаписывать существующие личные файлы. Он не запускает AI, не устанавливает пакеты и не обращается к внешним сервисам.

## Проверка настройки

```sh
python3 tools/doctor.py --workspace
```

Структурная готовность не подтверждает карьерные факты. Перед первым CV должны быть известны целевая роль, язык и достаточно исходного опыта. При отсутствии фактов можно оценивать требования вакансии, но нельзя заявлять соответствие кандидата.

## Первый полезный результат

Предложи пользователю одну вакансию, которую он сам выберет. Прочитай `skills/job-vacancy-analysis/SKILL.md` и сопоставь требования с его данными. Верни сильные стороны, пробелы и вопросы. Только если пользователь попросит сохранить или подготовить материалы, создай `applications/<company__role>/` и запись в трекере.

Ничего не отправляй работодателю. Подключение почты, календаря, облачного диска и другие внешние действия не являются частью онбординга.
